🤖 ROS (Robot Operating System) 概述

ROS Noetic 是 ROS 1 的最后一个长期支持版本，运行在 Ubuntu 20.04 上。 它不是一个传统意义上的操作系统，而是一个机器人软件框架，提供：

  • 进程间通信（发布/订阅、服务、动作）
  • 硬件抽象层
  • 包管理系统
  • 丰富的工具链（RViz可视化、rosbag录制回放、rqt调试）

核心概念

📦 Package（功能包）

ROS 中代码组织的基本单元。每个功能包包含：

  • package.xml — 包的元信息（名称、依赖）
  • CMakeLists.txt — 构建规则
  • launch/ — 启动文件
  • scripts/ — Python 脚本
  • src/ — C++ 源码

我们的功能包: mak4_sim

🔗 Node（节点）

ROS 系统中的最小执行单元，每个节点是一个独立进程：

# 查看正在运行的节点
rosnode list

# 查看节点信息
rosnode info /mavros

例如: /gazebo, /mavros, /laserMapping

📡 Topic（话题）

异步、单向的消息传递通道。发布者(Publisher)发送消息，订阅者(Subscriber)接收：

# 查看所有话题
rostopic list

# 查看话题数据
rostopic echo /mavros/state

# 查看话题频率
rostopic hz /mid360/points

📋 Message（消息）

话题中传输的数据结构，类似 struct：

# 常用消息类型
geometry_msgs/PoseStamped   # 位姿
sensor_msgs/PointCloud2     # 点云
sensor_msgs/Image           # 图像
nav_msgs/Path               # 路径
mavros_msgs/State           # 飞控状态

节点功能详解

🎯 PX4 SITL

PX4飞控固件的软件在环仿真。模拟真实飞控的全部功能：

  • EKF2: 扩展卡尔曼滤波器, 融合IMU+光流+测距仪
  • 位置/速度控制器: PID控制回路
  • 飞行模式: OFFBOARD, AUTO.LAND, POSITION等
  • 安全检查: 解锁条件、地理围栏

🔌 MAVROS

MAVLink协议到ROS话题的双向桥接:

  • 将PX4的传感器数据转为ROS消息
  • 将ROS控制指令转为MAVLink命令
  • 提供 /mavros/cmd/arming 等服务
  • 通过UDP连接到PX4 SITL

🗺 Fast-LIO2

高性能LiDAR-惯导紧耦合里程计:

  • 输入: LiDAR点云 + IMU数据
  • 输出: 配准点云地图 + 位姿轨迹
  • 使用 ikd-Tree 增量式KD树加速
  • 适合GPS拒止环境 (如大棚内)

🧊 OctoMap Server

3D占据栅格地图构建:

  • 将点云转换为八叉树表示的3D地图
  • 每个体素标记为: 占据/自由/未知
  • 用于碰撞检测和路径规划
  • 支持概率更新, 处理噪声

PX4 SITL 仿真

什么是 SITL?

Software In The Loop (软件在环) - 将PX4飞控固件编译为Linux可执行文件， 与Gazebo仿真器通过MAVLink通信，完全模拟真实飞行控制。

# PX4 SITL 启动流程:
#
# 1. PX4固件启动 → 模拟传感器 → EKF2融合 → 等待解锁
# 2. Gazebo启动 → 加载世界和模型 → 物理模拟 → 传感器模拟
# 3. PX4 ←→ Gazebo 通过 MAVLink 插件双向通信
# 4. MAVROS 连接到 PX4 (UDP 14540) → 转换为 ROS topics
#
# 位于: ~/PX4-Autopilot (v1.14.3)

MAVROS 是 MAVLink 协议的 ROS 封装。它将 PX4 飞控的所有数据通过标准 ROS 话题和服务暴露出来。

常用 MAVROS 操作

# 切换到OFFBOARD模式 (程序控制模式)

OctoMap 3D 占据栅格

OctoMap 将 Fast-LIO2 输出的配准点云转换为八叉树结构的3D占据概率地图。

  • 分辨率: 0.15m (每个体素边长)
  • 输入: /cloud_throttled (经降频到2Hz + 体素降采样的body帧点云)
  • 输出: /octomap_binary, /occupied_cells_vis_array
  • 可在 RViz 中以彩色3D方块可视化
  • max_range: 15m, hit/miss: 0.9/0.47, min/max: 0.12/0.97
  • ★ 第十七次TF修复: nan_filter改用body帧点云, OctoMap sensor origin正确
💡 OctoMap 问题终极诊断 (第十七次)
真正根因是TF, 不是参数! 之前nan_filter订阅/cloud_registered (frame_id=camera_init), OctoMap的frame_id也是camera_init。OctoMap计算sensor origin = TF(camera_init→camera_init) = (0,0,0)。 所有射线从世界原点出发, 而非无人机位置!
后果: 飞远后射线穿过之前建好的墙 → miss累积 → 墙壁瓦解。
修复: nan_filter改为订阅/cloud_registered_body (frame_id=body)。 OctoMap通过TF(body→camera_init)得到正确的无人机位置作为sensor origin。 同时移除冲突的静态TF (body→base_link, odom→map)。

OctoMap调参历史: 第13次max_range 20→5m(错), 第15次min=0.51(错), 第16次强hit+极弱miss(对但非根因) → 第17次TF修复才是根本解决。

📐 PCD切片 → 2D栅格导航 (推荐)

第十七次新增的业内主流方案, 完全不依赖OctoMap:

  1. 建图: FAST-LIO2 直接拼接全局3D点云 (.pcd), 建几公里不卡
  2. Z轴切片: pcd_to_2d_map.py 在飞行高度±0.3m处切片
  3. 投影: 切片点云压平→标准2D占据栅格 (.pgm+.yaml)
  4. 导航: 在2D栅格上做A*路径规划, 定高飞行避障
快速启动:

# 第二步: 生成2D地图
rosrun mak4_sim pcd_to_2d_map.py --height 1.0 --tolerance 0.3
# 第三步: 2D导航 (先启动mak4_greenhouse.launch)
roslaunch mak4_sim navigation_2d.launch
# 第四步: RViz点击航点 → 终端输入 start

终端命令: alt H 设高度 | speed S 设速度 | start 开始 | clear 清除 | stop 悬停 | home 返航

3D RRT* 局部避障

RRT* (Rapidly-exploring Random Tree Star)

RRT* 是 RRT 的渐近最优变体，在 OctoMap 3D 地图中规划无碰撞路径：

  1. 随机采样: 在3D空间中随机选点 (15%概率偏向目标点)
  2. 最近节点扩展: 向随机点方向延伸一步 (步长0.5m)
  3. 碰撞检测: 查询OctoMap, 检查路径是否穿过障碍 (安全半径0.3m)
  4. 重连优化: (RRT*特有) 检查是否可以通过新节点降低附近节点代价
  5. 路径平滑: 贪心跳点法去除冗余航点
